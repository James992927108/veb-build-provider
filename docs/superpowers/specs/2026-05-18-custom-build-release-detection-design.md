# Custom Build Release Detection — Design Spec

**Date:** 2026-05-18  
**Status:** Approved

## Problem

When the user presses F8 (initTask) on a project that has a `GB300_Release_Build.sh` script,
the generated `CustomBuild.sh` is currently an empty template with only comments.
The user has to manually edit it to call the release build script.

## Goal

F8 should auto-detect `GB300_Release_Build.sh` in the project root and pre-configure
`CustomBuild.sh` to call it with the `$VEB` variable, so VebCustomBuildTask (via F7 → select)
runs the release build immediately without any manual editing.

## Scope

- One function: `BuildDefaultTask` in `src/veb-build/commands/buildCommands.ts`
- Linux path only (the `else if (targetEnvironment === 'linux')` branch)
- No new commands, keybindings, or tasks required

## Design

### Detection

```typescript
const releaseBuildScript = path.join(folderpath, 'GB300_Release_Build.sh');
const hasReleaseBuild = await fs.access(releaseBuildScript).then(() => true).catch(() => false);
```

Runs immediately before writing `CustomBuild.sh`, after `PrepareEnvLinuxScript.sh` is written.

### CustomBuild.sh — when `GB300_Release_Build.sh` is detected

```bash
#!/bin/bash
# VEB Build Provider - Custom Build Script
# Auto-configured: GB300_Release_Build.sh detected in project root
#
# VEB is injected by VebCustomBuildTask via tasks.json options.env.VEB
# To build a different VEB, run F8 and select another .veb file

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"

chmod +x "$PROJECT_ROOT/GB300_Release_Build.sh"
"$PROJECT_ROOT/GB300_Release_Build.sh" "$VEB"
```

`SCRIPT_DIR` resolves to `.vscode/`, `PROJECT_ROOT` resolves to the workspace root.
`$VEB` is set by `VebCustomBuildTask`'s `options.env.VEB` (hardcoded by F8 to the selected VEB name).

### CustomBuild.sh — when NOT detected (current behaviour, unchanged)

```bash
#!/bin/bash
# VEB Build Provider - Custom Build Script
# Auto-generated by VEB Build Provider
#
# This script is called by VebCustomBuildTask
# Environment variables available:
#   VEB           - Current VEB project name (currently: <Veb>)
#
# Examples:
#   ./GB300_Release_Build.sh GB300Standard
#   ./GB300_Release_Build.sh $VEB
#
# Add your build commands below:
```

### $VEB Flow

```
F8 selects "GB300Ali.veb"
  → tasks.json written with options.env.VEB = "GB300Ali"
  → User presses F7 → selects VebCustomBuildTask
  → Task runs: source PrepareEnvLinuxScript.sh && .vscode/CustomBuild.sh
  → Shell env has VEB=GB300Ali
  → CustomBuild.sh calls: GB300_Release_Build.sh "GB300Ali"
```

## What Does NOT Change

- No new VSCode commands or keybindings
- No changes to tasks.json template
- No changes to Windows path
- Existing `VebReleaseBuildTask` in tasks.json continues to work as before
- If `CustomBuild.sh` already exists, it is overwritten (consistent with current F8 behaviour)
